# 2026-09 优化与验收记录

## 录音与字幕隔离

新增持久 ASR isolate、单消息 ACK、8 秒有界队列、启动/处理/收尾超时。
音频先落盘，字幕失败不阻止录音；结束时音频先完成，再等待字幕最终清单。
增加并发/延迟/失败/暂停 FIFO 测试。恢复清单改为串行原子替换。
注意这不是进程隔离：native crash、系统强行停止、存储写入失败仍需专门处理和验收。

## 中英离线识别

- 引擎固定 sherpa-onnx 1.13.8；保留原中文 14M 模型，增加 small bilingual zh-en INT8（约 47 MB）。
- 热词用 CJK+BPE 分词及 modified beam search；中文低负载模式无热词时保留 greedy search。
- 两套模型均带 SHA-256，模型文件在安装包内，首次安装后不依赖网络。
- 新增手机“验证当前离线模型”按钮，不调用麦克风或云端。

### 可复现的小样本检查

运行：`uv run --with sherpa-onnx==1.13.8 --with numpy python tool/benchmark_asr.py`。
输入是官方模型包中 10.053 秒、4.690 秒的两段中英夹杂示例，不是用户录音。
Mac 本次测得：中文模型把星期词和 FREQUENTLY 音译为错误中文；双语模型能输出
MONDAY、DAY AFTER TOMORROW、FREQUENTLY，但仍有漏词和中文错误。
双语模型的两段解码 RTF 约 0.09 / 0.114（小于 1 表示本机解码快于音频长度）。
这只是宿主机烟雾测试，不是手机耗电/实时性或一般会议准确率指标。

排查中同一 Python 测试在 1.13.4 返回异常少的文字，1.13.8 恢复；这足以要求升级并回归，
但不能据此把用户此前的所有识别问题都归因于版本。远场音质和领域词依然重要。

## PPT 拍摄与扫描

普通相机改为连续拍摄和最高分辨率请求，增加变焦、生命周期代次检查、保存完成计数，
移除逐张备注弹窗，缩略图离线处理移至 isolate。原图不改写。
Android 扫描桥使用 ML Kit 16.0.0 单页 JPEG、原生扫描 UI；通过本地 JSON 恢复日志和固定 ID
避免 Activity 重建后的结果丢失/重复节点。相册入口保留。
扫描 SDK 不暴露原始快门时间和未处理图，界面与备注明确提示入口时间及扫描操作范围。
该模式不能承诺照片/音频误差低于 2 秒；普通连拍仍按按下快门前的单调时钟记录。

## 真机发现的问题及追加修复

- 高分辨率连拍时，Dart 全尺寸解码缩略图导致下一张等待数秒。Android 改用
  `BitmapFactory.inSampleSize` 原生后台降采样、EXIF 方向修正和最长边 480 的 JPEG 缩略图，
  原图仍逐字节保留；其他平台保留 isolate 实现。
  参考 [Android 大图加载文档](https://developer.android.com/topic/performance/graphics/load-bitmap)。
- release 包第一次启动扫描器触发 `SharedPrefManager` 空引用。反混淆及 SDK 字节码
  定位到扫描器内部初始化，与 [ML Kit 的 AGP 9 / R8 问题](https://github.com/googlesamples/mlkit/issues/1018)
  相似。为相关 ML Kit 包增加定向 keep 规则，并捕获同步初始化异常，清除 pending 状态以允许重试。
  错误提示不再暴露整段 native 堆栈遮挡控制按钮。修复是否生效以 release 真机复测为准。
- 4006 release 真机复测已进入 Google 扫描界面并完成拍摄、裁边预览。保存阶段进一步发现
  `BitmapFactory.Options.inSampleSize` 默认值是 0，初版缩略图出现除零错误；4007 明确从 1
  计算采样比例，增加 4 项 Kotlin/JUnit 边界测试，均已通过。失败扫描未被 acknowledge，
  原件与恢复日志仍保留，待再次进入现场页导入。

  未使用麦克风、未上传。英文可输出但仍漏词，不能据此声称现场识别准确。

- 静态分析无问题；最新 Flutter 全套 59 项测试通过，包括 native 缩略图通道、fallback、
  存储错误传播、平台异常提示长度；不等同于 Android 图像像素算法/长时录音全部通过。
